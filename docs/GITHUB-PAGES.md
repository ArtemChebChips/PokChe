# PokChe на GitHub Pages

Подготовлена автоматическая публикация в `.github/workflows/pages.yml`. Отдельный сервер и сторонний хостинг не требуются. Имя репозитория может быть любым: базовый путь получает GitHub Actions из настроек Pages. Поддерживаются и адрес вида `https://USERNAME.github.io/REPO/`, и корень сайта.

## Один раз

1. Загрузить исходники проекта в нужный GitHub-репозиторий, ветку `main`. `node_modules`, `dist` и результаты тестов загружать не нужно.
2. Открыть **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. В **Actions → Publish PokChe → Run workflow** запустить публикацию, если она не началась автоматически.
4. Когда публикация завершится, открыть ссылку в задаче `deploy` или в Settings → Pages.

После этого каждый push в `main` проверяет правила, собирает PWA и публикует новую версию. Для репозитория с другой основной веткой измените фильтр `branches` в workflow.

## На телефоне

Открыть опубликованную ссылку с интернетом. На iPhone: Safari → «Поделиться» → «На экран Домой». На Android: Chrome → ⋮ → «Добавить на главный экран» / «Установить». В установленном приложении открыть настройки и дождаться готовности офлайн-копии. Дальше уроки и базовые тренировки работают без сети; уведомления не запрашиваются.

Прогресс каждого друга хранится на его устройстве. Ссылка сама по себе не ограничивает доступ: в текущей версии нет пароля или аккаунтов. Изменение адреса сайта может потребовать переноса прогресса через экспорт/импорт JSON.

## Локальная проверка адреса с подпапкой

PowerShell:

```powershell
$env:PAGES_BASE_PATH='/PokChe/'
npm run build
$env:PLAYWRIGHT_CHANNEL='chrome'
$env:E2E_PATH='/PokChe/'
npm run test:e2e
```

Переменная `PAGES_BASE_PATH` задаёт пути скриптов, манифеста, иконок, service worker и офлайн-страницы. Без переменной остаётся локальный адрес `/`.

Основа настройки: [официальная инструкция Vite для GitHub Pages](https://vite.dev/guide/static-deploy.html#github-pages).
