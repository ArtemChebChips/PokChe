# PokChe — рабочий план продолжения
Дата: 19 сентября 2026. План описывает поэтапную работу. Разработка этапов A и B начата; актуальное состояние — ниже.

## 1. Зафиксированные решения

- Личное приложение для владельца и одного-двух друзей: простое, красивое, полезное, с ненавязчивым юмором.
- Продолжаем существующий Vite + React + TypeScript. PWA через GitHub Pages: https://artemchebchips.github.io/PokChe/. Новый проект, сервер, регистрация, синхронизация, рейтинги, платежи и уведомления не нужны.
- Одна вертикальная мобильная версия; на компьютере та же компоновка ограниченной ширины.
- Дизайн: design/mobile-refinement/02-mint-fixed.png. Поздние указания пользователя важнее раннего упоминания кремового фаворита в README.
- Логотип — пика с круглыми ушами и белыми внутренними кружками; название PokChe; без «Бета».
- Убрать прежние лозунги, декоративный курсив и огромные вводные блоки. Сохранить полезные названия уроков и краткое содержание.
- Нижняя навигация компактная: книга, мишень, график. Подписи «Обучение», «Тренажёры», «Мой прогресс». Небольшие иконки не означают мелкие области нажатия.
- На главной отдельно прокручивается список модулей; шапка и нижняя панель закреплены. Верхний блок и текущий урок компактные, чтобы список имел полезную высоту. Нет «Все 13 модулей» и отдельного экрана ради списка. Пройденное доступно повторно.
- Урок — объяснение и иллюстрации. Практика начинается отдельно, после чтения или напрямую по выбору пользователя.
- Каждый новый термин сначала объясняется. В задаче определение можно открыть повторно.
- Использовать готового Иваныча из design/sava/assets-v1/. Новые позы пока не заказывать.
- Небольшие понятные компоненты, обычный CSS, локальные данные. Без универсального движка уроков, сложной дизайн-системы, нового менеджера состояния и инфраструктуры ради будущего.

## 2. Что сохраняем и что исправляем

Сохраняем публикацию, математическое ядро, независимые проверки, Web Worker, локальный прогресс, экспорт/импорт, три раздела и карту тем 0–12. Код не переписываем с нуля.

Сейчас есть девять коротких материалов и одиннадцать тренажёров. В предыдущей реализации проходили 16 проверок правил/генераторов/сохранения и четыре браузерных сценария. Это исходная точка, а не утверждение о новом прогоне тестов.

Исправляем прежде всего: вопросы внутри чтения, чрезмерную случайность и простоту упражнений, условные карты, отсутствие учебного стола, необъяснённый сленг, слишком большой верх экрана и отсутствие выбранного оформления.

Дизайн-файлы другого агента лежат отдельной незакоммиченной папкой design. Не перезаписывать её и не публиковать все исходники автоматически. В сборку включать только выбранные рабочие ассеты.

## 3. Этап A — новая главная и базовое оформление

Действие пользователя: сейчас отправить дизайнеру сообщение A из docs/DESIGNER-BRIEFS.md.

Пока он готовит графику:
- Проверить существующий прогресс и возможность резервного экспорта; сохранить контрольную версию кода.
- Отформатировать изменяемые файлы. Выделить по необходимости оболочку приложения, кнопку, строку урока, карту, панель Иваныча и отдельные экраны. Без большого предварительного рефакторинга.
- Завести несколько CSS-переменных палитры, отступов и скруглений. Использовать один читаемый шрифт с кириллицей; системного или локального шрифта достаточно. Внешний запрос шрифта для запуска не нужен.
- Собрать главную: компактная шапка, текущая тема, список, нижняя навигация.
- Реализовать отдельную прокрутку списка и возврат на прежнее место после урока.
- Убрать лозунги, «Бета», курсив; графику текущего урока держать небольшой.
- Пройденная строка открывает материал повторно. Прямой доступ к тренировкам остаётся.
- У доступных тем нет искусственных замков. Будущие темы имеют честный статус подготовки.
- Считать модули и короткие уроки раздельно. В программе 13 модулей; завершение одного короткого урока не всегда означает завершение модуля.
- Проверить пакет A и подключить рабочие копии. Оригиналы дизайнера сохранить.

Критерий: главная соответствует мятному референсу, понятна без вступления, список удобно прокручивается. На 320 px, 390×844, коротком экране и при увеличенном тексте ничего не перекрыто. Основные области нажатия около 44 px и больше. Малый экран не должен оставлять список высотой в одну строку.

## 4. Этап B — нормальная колода и один законченный учебный сценарий

Действие пользователя: после проверки общего стиля пакета A отправить дизайнеру сообщение B. Пока делаются фигуры, работаем над геометрией колоды, чтением и генераторами.

### Карты
- Один компонент с пропорцией примерно 5:7.
- Достоинство и масть сверху слева; такие же индексы снизу справа, повёрнутые на 180°.
- На карте десятка пишется 10. Обозначение T объясняется отдельно при чтении покерной записи.
- Для 2–10 точно расставлять символы масти программно, для A — крупную масть, для J/Q/K — три различимых рисунка.
- Один рисунок достоинства можно использовать для всех четырёх мастей: нужные индексы и масть добавляются интерфейсом.
- Все 52 карты собираются из данных. Сгенерированные декоративные картинки не являются источником правильных ответов.
- Крупные карты в сравнении, компактные на доске. Семь карт при необходимости переносятся рядами. Выбор виден по отметке и контуру, а не только цвету.

### Урок 00
- Несколько коротких сцен: колода; масти; числовые достоинства; валет, дама и король с полными названиями; туз; памятка.
- Одна мысль на сцену, иллюстрация, короткий текст, назад/далее. Нет обязательного вопроса перед продолжением.
- Показать ряд J → Q → K → A с последовательным выделением. Демонстрацию можно повторить, смысл понятен без анимации.
- Младший туз — только после объяснения последовательности из пяти карт. Полноценные упражнения на стрит разумно вводить в модуле комбинаций.
- В конце «Тренироваться», но чтение можно закончить без запуска задач.
- Запоминать место чтения. «Продолжить» открывает его; «Повторить» позволяет начать сначала.
- «Материал прочитан» и «навык освоен» — отдельные состояния.

### Полезный тренажёр 00
Обычная пятёрка управляется простым планом:
1. Три задачи на J/Q/K/A; обязательно сравнение двух фигур J/Q/K. За несколько сессий покрыть пары, не отдавая всё тузам.
2. Одна задача с тузом против другого достоинства в обычном сравнении: туз здесь старший.
3. Одно закрепление: равные достоинства разных мастей, чтение обозначений либо числовое сравнение. Чистых сравнений двух чисел максимум одно на пятёрку.

Меняются масти, порядок и конкретные примеры; учебная цель не выпадает случайно. Не повторять буквально одинаковые пары внутри одной сессии, избегать однообразия между соседними сессиями.

После ошибки — точное объяснение («Дама старше валета: J → Q → K»), визуальное выделение и похожая задача на тот же навык. Похожая задача может заменить следующий подходящий пункт или стать явным дополнительным упражнением; не запускать неожиданно новую сессию вместо текущей.

Не делать туз младшим при сравнении двух отдельных карт. Это свойство только явно заданного стрита A–2–3–4–5, после объяснения правила.

### Иваныч
- Первое знакомство короткое, с пропуском; повторно не навязывать.
- thinking для подсказки по запросу, explain для разбора, try-again после ошибки, celebrate в итогах.
- Высота примерно 110–160 CSS px по месту. Не перекрывать карты, ответы или нижнюю панель.
- Реплики обычным текстом; облачко и появление средствами интерфейса. Поддержка и лёгкий юмор, без насмешек и длинных речей.
- Смысл разбора определяется учебными данными, а не случайной фразой персонажа.
- Не показывать крупное модальное окно после каждого ответа. Все основные действия работают без ожидания анимации.
- Сохранять детали персонажа; не зеркалить часы. Это отдельные позы, не готовые кадры анимации. Учитывать reduced-motion.
- cheers оставить необязательной пасхалкой на потом.

Критерий: один полный сценарий в новом качестве — чтение → практика → разбор → похожая задача → сохранение → повторение. Пользователь пробует его на телефоне до распространения подхода на все темы.

Проверки: состав пятёрок, корректность ответов, чёткое разделение роли туза, сохранение и офлайн-работа, понятность на маленьком экране.

## 5. Этап C — базовые уроки с наглядными объяснениями

### 01. Комбинации
Разделить на короткие материалы: виды и старшинство; лучшая пятёрка; кикеры; делёж.
Показывать конкретные карты и выделять решающую часть комбинации.
Обязательно: младший стрит; невозможность K–A–2–3–4; флеш против стрита; две тройки; три пары; неиспользуемые шестая/седьмая карты; общая доска и ничьи.
Сначала выбирать семейство учебного случая, затем допустимые карты и проверять результат ядром. Редкие важные комбинации должны появляться целенаправленно.

### 02. Ход раздачи
Сначала объяснить банк, фишки, блайнды, личные/общие карты и кнопку дилера.
Показать последовательность префлоп → флоп → тёрн → ривер → вскрытие. Объяснить «улицу» и «постфлоп», прежде чем задавать вопросы с этими словами.
Фолд, чек, бет, колл, рейз, олл-ин показать движением фишек. «Следующий шаг» в демонстрации не является проверочным вопросом.
Различать «повысить до» и «добавить»; показывать уже вложенную сумму.
Сначала правила для 6-max; heads-up не смешивать без отдельного объяснения.

### 03. Позиции, стеки и SPR
Сделать переиспользуемый стол SVG/HTML: шесть мест, кнопка дилера, блайнды, банк, карты и выделение очереди.
Писать полные названия: ранняя позиция (UTG / Under the Gun), хайджек (HJ / Hijack), катофф (CO / Cutoff), баттон (BTN / Button), малый блайнд (SB / Small Blind), большой блайнд (BB / Big Blind).
Показать отличие очереди на префлопе и постфлопе, включая пропуск выбывших. Объяснить пользу последнего слова.
Стеки в BB, эффективный стек один на один, стартовый и оставшийся стек, затем SPR.
Если ответ выбирается на столе, продублировать крупными кнопками.

### Кэш и турниры
Вводный урок после позиций, без требования пройти всю программу.
Разобрать блайнды, докупку, выбывание и призы. Направление сохранять без сброса общих навыков.
Первые стратегические данные — кэш 6-max / 100 BB только после проверки источника. Турнирный выбор влияет на рекомендации по общей базе; кэшовую задачу не выдавать за турнирную.

Новая графика столов, стрелок и подписей обычно не нужна: это элементы интерфейса.
Критерий: новичок видит происходящее и понимает термины до практики.

## 6. Этап D — стартовые руки, математика и доска

- Модуль 04: пары, suited/offsuit, запись рук, доминация, разница между конкретной комбинацией и типом руки. Матрица 13×13 с крупной выбранной клеткой, действиями и альтернативным списком. Пока это изучение записи, а не чарт открытия.
- Модуль 06: отдельные короткие уроки об аутах, эквити, шансах банка, EV и простых моделях блефа. Сначала конкретный пример, потом формула.
- SPR доступен отдельно и связан со стеками. Не превращать одно число в рекомендацию действия.
- Модуль 07: масти, пары и связанность доски; готовая рука/дро; флеш-дро, двустороннее стрит-дро, гатшот; изменения после следующей карты; нечистые ауты.
- Для эквити выбирать смысловые сценарии: пара против дро, доминация, делёж, нечистые ауты. Сохранять полный перебор на тёрне против явно показанной руки.
- Заранее объяснять точность ответа: округление или допустимое отклонение. В разборе точное значение, число исходов, учёт ничьих.
- Флоп и небольшие явно заданные диапазоны — последующее расширение, если нужны для урока. Для диапазона показывать состав/веса, исключать заблокированные комбинации, нормировать веса, независимо проверять расчёт.
- Расчёт в worker или заранее. Если позже понадобится симуляция, хранить и показывать метод, число испытаний и погрешность.
- Не подменять эквити стратегией: сравнение с ценой колла достаточно только в оговорённой модели, например при олл-ине один на один без рейка и будущих ставок.

Критерий: задача тренирует определённое понимание; её исходные условия доступны, а ответ воспроизводим.

## 7. Этап E — ежедневная практика и прогресс

Эти механизмы вводятся уже в первом сценарии и доводятся по мере добавления навыков.
- Короткие сессии, прямой выбор темы, смешанный режим и повторение ошибок.
- Смешанный режим по умолчанию использует изученные навыки и повторения. Опытный пользователь выбирает любые доступные упражнения напрямую.
- Сначала план видов задач, потом генерация конкретных допустимых вариантов. Гарантировать важные случаи, не только случайную раздачу.
- Ошибки сохранять по поднавыкам и типам заблуждений вместе с условиями и версией задачи.
- Успешное повторение закрывает конкретную ошибку; похожий пример проверяет понимание вне заученного ответа.
- Простое возвращение ошибок в следующую сессию и следующее посещение. Сложный алгоритм интервального повторения не нужен.
- Статусы «прочитано», «тренировался», «стабильно отвечаю»; ответы с подсказкой отдельно от самостоятельных.
- Экран прогресса: практика, результаты по навыкам, слабые места и повторение. Без соревнования с друзьями и навязчивых серий дней.
- Существующие данные не обнулять. При изменении формата сделать небольшую явную миграцию и резервную копию. Устаревший текст задачи не выдавать за обновлённое задание.
- Сохранить экспорт/импорт, обработку повреждённого сохранения и честное сообщение при сбое записи.
- Продолжение урока и прерванной сессии без двойного учёта уже проверенного ответа.

Критерий: можно зайти на несколько минут, получить полезную практику, закрыть приложение и вернуться без потери результатов.

## 8. Этап F — достоверная стратегия

Поиск данных можно продолжать независимо, он не блокирует базовое обучение. Прежняя проверка записана в docs/SOURCES.md; перед подключением сведения проверяются заново.

- Конкретный набор с понятным происхождением и допустимым использованием либо воспроизводимый собственный расчёт.
- Сохранить формат игры, число игроков, стеки, блайнды, анте, рейк и cap, размеры ставок, условие входа в ситуацию, версию и ссылку.
- Различать учебный чарт и вывод солвера. Бесплатный просмотр или подписка сами по себе не разрешают перенос базы.
- Не придумывать EV, частоты и «GTO-оптимальность».
- Модуль 05: сначала открытия; ответы на рейзы, 3-беты и защита блайндов только при наличии подходящих данных.
- «Собери диапазон» с оценкой включать после проверки источника. Клетка выбирается, действие/доля задаются крупной панелью; доступен выбор без точного закрашивания пальцем.
- Для учебного чарта оценивать соответствие выбранной стратегии. Для солвера — EV в той же модели с учётом точности и нескольких допустимых хороших действий.
- Редкое действие не считается ошибкой из-за низкой частоты; частоты оценивать отдельно на серии.
- Для постфлопа проверить ограничения, лицензию и воспроизводимость b-inary/postflop-solver перед интеграцией. При необходимости подготовить небольшую базу заранее без серверного сервиса.
- Исходные диапазоны, доска, стеки, дерево ставок и параметры расчёта сохраняются. Любое изменение условий требует нового расчёта.
- В задачах на принятие решения скрытые карты соперника не показываются до ответа.
- Если источник не подтверждён, раздел остаётся в подготовке; другие этапы продолжаются.

Вводный урок о форматах идёт после 3. Короткие стеки и пуш/фолд требуют префлопа и математики; ICM — EV и структуры выплат. Показывать рекомендуемую подготовку, опытному пользователю разрешать прямой переход. Турнирная стратегия — отдельное расширение. Переключатели профилей появляются только для существующих наборов.

Дополнительно: короткие отдельные материалы о дисперсии, тильте, банкролле и самостоятельном разборе. Они не блокируют основную программу.

Новые иллюстрации для поздних тем заказывать только под конкретное объяснение, используя сообщение C.

## 10. Проверки и публикация

На каждом законченном этапе:
- Сохранять независимые проверки правил: младший стрит, кикеры, общая доска, ничьи, запрещённые повторы карт, очередь, шансы банка, SPR и эквити.
- Добавить содержательные проверки состава сессий: важные типы гарантированно встречаются. Проверка только правильности случайных ответов недостаточна.
- Обновить браузерный цикл под чтение без опроса: урок → практика → ошибка → разбор и похожая задача → итог → перезагрузка → повторение.
- Проверять старые сохранения, экспорт/импорт, продолжение без двойного учёта.
- Визуально проверять карты, выделения, крупные зоны нажатия, прокрутку и отсутствие перекрытий. Никаких действий только по наведению.
- Первый сетевой запуск загружает необходимые материалы, ассеты и worker. Сообщение «готово офлайн» соответствует фактической готовности кэша.
- Проверять запуск без сети, расчёты и запись прогресса, обновления без неожиданной перезагрузки сессии.
- Проверять базовый путь /PokChe/: иконки, манифест, service worker, скрипты и офлайн-переходы.
- Публиковать законченными порциями существующим GitHub Actions. Проверять успешный deploy и настоящий адрес сайта.
- Пользователь и друг проверяют установку и удобство на физических телефонах. Их модели уточнить перед этой проверкой, не задерживая старт разработки.

После каждой порции: что изменено, что проверено, что ещё ограничено. Не обещать физическую проверку iPhone по результатам эмуляции.

## 11. Простая реализация

Сохранить отдельные poker.ts, tasks.ts, content.ts, progress.ts, strategy.ts и worker. По мере работы выделять конкретные экраны из App, без универсальных слоёв.

Урок — обычный список сцен с текстом и типом иллюстрации. Практика — генераторы навыков и план сессии. Иваныч — один компонент с позой и репликой. Прогресс — локальные данные с версией. Стратегия — явные наборы со своим происхождением. Этого достаточно.

## Приоритетные уточнения после проверки пользователем урока 0

Эти требования заменяют противоречащие им пункты выше.

- Работаем по одному уроку. До наполнения следующего описываем учебную цель, порядок коротких страниц, понятия, конкретные примеры и необходимые изображения. Не переносим черновые тексты массово в приложение.
- Урок — понятный учебник без заполнения страниц общими фразами. Формальные определения допустимы. Объяснение записи T перенести к обозначениям рук; объяснение рубашки из урока 0 убрать.
- В уроке 0: трефы (крести), ясное старшинство чисел и фигур, отдельная страница туза, итоговая иллюстрация всех 13 достоинств. Равенство мастей формулировать применительно к сравнению достоинств; масть важна для некоторых комбинаций.
- Масти в карточном компоненте рисовать вектором. Фигуры использовать из пакета B. Центральные символы должны иметь собственную высоту: найдено, что прежняя автоматическая высота схлопывалась и символы накладывались.
- Иваныч — крупный персонаж без общей рамки, отдельным визуальным слоем рядом с облаком речи. Не закрывает текст и кнопки. Обычные объяснения даёт интерфейс; Иванычу оставляем советы и подсказки по запросу. Не показываем его после каждого ответа. Реплики начинаются с заглавной буквы.
- Тренировка — один экран с одной задачей. После ответа можно продолжить или закончить. Внутренняя генерация пачками не должна навязывать пять задач пользователю. Итог считается по реально проверенным ответам. Правильный ответ сопровождает короткое конфетти без блокировки действий; reduced-motion отключает эффект.
- Итог урока называется «Урок пройден».
