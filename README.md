# PokChe — покер по шагам

Личное русскоязычное PWA на Vite + React + TypeScript. Один мобильный интерфейс шириной до 480 px, в том числе на компьютере. Аккаунты, серверная база и платные сервисы не нужны.

Приложение опубликовано на **GitHub Pages**: https://artemchebchips.github.io/PokChe/. Изменения в main публикуются автоматически. [Настройка и установка на телефон](docs/GITHUB-PAGES.md).

## Запуск

Нужен Node.js 22.12+ (проверено на 24.18).

```sh
npm ci
npm run dev
```

Для проверки установки и офлайн-режима нужна production-сборка:

```sh
npm run build
npm run preview -- --port 4173
```

Откройте http://localhost:4173 на компьютере. `dev` не регистрирует service worker. На телефоне используйте опубликованный адрес GitHub Pages. Запуск по HTTP-адресу компьютера в локальной сети позволяет посмотреть интерфейс, но не обеспечивает полноценную установку и офлайн-режим.

## Установка на телефон

1. Откройте HTTPS-адрес приложения с интернетом.
2. **iPhone:** Safari → «Поделиться» → «На экран Домой». В версиях с пунктом «Открывать как веб-приложение» включите его.
3. **Android:** Chrome → ⋮ → «Добавить на главный экран» → «Установить». Названия пунктов могут отличаться.
4. Откройте приложение с нового значка и в настройках дождитесь сообщения «Базовые материалы готовы офлайн». После этого уроки, все 17 тренажёров и расчёты доступны без сети.

Инструкции производителей: [Apple](https://support.apple.com/guide/iphone/open-as-web-app-iphea86e5236/ios), [Google Chrome](https://support.google.com/chrome/answer/9658361?co=GENIE.Platform%3DAndroid&hl=en).

Прогресс сохраняется в `localStorage` этого браузера и адреса, без синхронизации. Safari и установленное приложение могут иметь отдельное хранилище. Используйте экспорт/восстановление JSON в настройках. Очистка данных сайта или удаление приложения могут удалить сохранение; ОС также может вытеснить офлайн-кэш. Для обновления приложение предлагает отдельную кнопку, не перезагружая активную тренировку.

## Реализовано

- 13 основных уроков 00–12 и дополнительная «Игра вдолгую»: 14 доступных материалов. Перед новыми уроками составлены отдельные планы. Чтение, главы, закладки и практика разделены.
- 17 тренажёров: от карт и комбинаций до эквити диапазона, EV ставки, связанных решений тёрн → ривер, статистики наблюдений, блокеров и частот.
- Целевые семейства задач вместо случайных досок без учебной цели. Полный перебор риверов и взвешенного диапазона, точные условия моделей. Несколько равноценных действий принимаются как правильные.
- Пять собственных ограниченных риверных игр, рассчитанных SciPy/HiGHS и независимо сверенных формулами. [Условия и воспроизведение](docs/RIVER-PILOT.md).
- Общий стол с готовыми ассетами, фишками, круглыми позициями и улучшенной объёмной D. Масштабируемые карты. Интерактивный калькулятор линии и просмотр частот модели.
- Свободная и смешанная практика, объяснения, подсказки, сохранённые ошибки и похожие задачи. Освоение новых тем требует разных семейств, а не повторения одного ответа. Чтение учитывается отдельно.
- Локальный прогресс, экспорт/импорт, офлайн-PWA. Кэш и турниры объяснены на отдельной странице настроек; выбор предпочтения сохраняется.

## Ограничения

Стратегические чарты открытий и ответов на 3-бет ещё не подключены: нужен набор с проверенными параметрами и правами использования. Доступная префлоп-практика учит правилам действий, цене и размерам, а не оценивает оптимальность стартовых рук. [Состояние источников](docs/SOURCES.md).

Риверные игры имеют синтетические диапазоны и узкое дерево чек/ставка → пас/колл. Это точные ответы внутри описанной модели, не полноценный постфлоп-солвер и не общая стратегия холдема. Турнирная программа, ICM, сайд-поты и особые правила heads-up остаются будущими расширениями. Переключение предпочтения в настройках не превращает кэшовые ответы в турнирные.

Синхронизации между устройствами нет. Незавершённая тренировочная сессия после перезагрузки не восстанавливается; уже проверенные ответы и ошибки сохраняются сразу. Мобильные браузерные тесты не заменяют проверку установки и обновления на физическом iPhone.

## Проверки

```sh
npm test
npx playwright install chromium
npm run test:e2e
```

`tests/poker.test.ts`: крайние случаи правил, генераторы, сохранение, независимое сравнение 1000 пар рук с `pokersolver`, независимая проверка 25 полных переборов на тёрне. Случайная выборка для независимой проверки воспроизводима фиксированным seed.

`e2e/app.spec.ts`: мобильный цикл урока/тренировки/повторений, сохранение после перезагрузки, service worker и задачи при отключённой сети, матрица на 320 px и выбор пяти карт. Браузерные проверки эмулируют экран телефона, но не заменяют проверку установки на физическом iPhone/Android.

Если Chrome уже установлен, можно обойти загрузку Chromium. В PowerShell: `$env:PLAYWRIGHT_CHANNEL='chrome'`, затем `npm run test:e2e`.

52 unit-теста проверяют правила, независимые результаты pokersolver, диапазоны, интервалы статистики, банк между улицами, альтернативы и совместимость сохранений. Браузерная приёмка охватывает 40 сценариев; после общего прогона затронутые сценарии повторяются отдельно.

## Структура

- `src/poker.ts` — правила и полный перебор.
- `src/tasks.ts` — генерация условий и оценка ответов.
- `src/training.worker.ts` — вычисления вне основного потока.
- `src/content.ts` — уроки и карта программы.
- `src/progress.ts` — состояние, проверка сохранений, освоение навыков.
- `src/strategy.ts` — схема происхождения префлоп-данных; активный внешний чарт отсутствует.
- `src/rangeMath.ts`, `src/advancedTasks.ts` — диапазоны, EV, статистика и связанные задачи.
- `src/data/river-models.json` — собственный ограниченный рассчитанный набор.
- `src/App.tsx`, `src/style.css` — мобильный интерфейс.
- `vite.config.ts` — сборка, манифест и офлайн-кэш.

Графика пакета A подключена в `public/art`, Иваныч — в `public/sava`. [Состояние графики](docs/ASSET-INTEGRATION.md). Пакет B подключён: рисунки J/Q/K и рубашка находятся в public/cards и доступны офлайн. `package-lock.json` фиксирует фактически установленные версии зависимостей.

Для проверки пути GitHub Pages в PowerShell установите `$env:PAGES_BASE_PATH="/PokChe/"` перед сборкой и запуском preview, а также `$env:E2E_PATH="/PokChe/"` перед браузерными тестами.
